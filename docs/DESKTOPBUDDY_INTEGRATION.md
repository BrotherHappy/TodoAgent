# DesktopBuddy 集成与验收

目标：直接使用 DesktopBuddy 的角色、Live2D 动画和互动机制，保留 TodoAgent 的任务、飞书、Agent、番茄钟与安全边界。

上游：<https://github.com/DCDingCong/desktopbuddy>，核对版本 `af736aab52c1a2b9caae8a3216ce016167577733`。

## 资源与实现事实

- 5 个原版 Live2D 主题：Hiyori、Wanko、Rice、Mark、Haru。各自有原版模型、纹理、动作、物理和专属互动映射。默认 Wanko，已选角色在本机记忆。
- 上游的 33 帧生成器对一张图做缩放、旋转、平移和颜色变换，**不是生成 33 张新的肢体绘画**。输出是 1 张基准图 + 33 张状态帧；每个勾选的补充动作增加 33 帧，默认 3 项共 133 张。保留这个离线能力，同时提供连续时间运动与补充动作序列；不能把图片变换宣传成 Live2D 骨骼动画。
- 上游代码 MIT；Live2D 模型和 Cubism Core 使用独立条款，不能一并标为 MIT。保留角色名称、设计与来源，不对 Hiyori 改装或重新着色。
- 版权声明和原始许可放入 `assets/desktopbuddy/licenses`，随应用打包；公开发布前应按实际发行主体核对 Live2D 的发布许可要求。

## 怎么使用

1. 打开「设置 → Todo Pet」，在「选择你的桌面伙伴」中切换原版角色，预览下方可点击其专属互动。宠物展开小窗的「小窝」也有同一组互动。
2. 同一区域可分别调整重力、惯性、边缘吸附、呼吸、眼神跟随、减少动态效果、四种人格和记忆轮数。关闭「与 Todo Pet 同步人格」后，Agent 使用独立设置。
3. 选择「用一张图片生成动画」，提供不超过 5MB、8192px 的 PNG/JPEG/WebP；填写名字、勾选补充动作，然后生成并切换。支持取消；不上传图片、不调用生图模型。ZIP 导入限 96MB、2,000 个条目，单文件解压限 30MB。
4. 已配置的 Agent 可直接用于宠物，无需再次填写模型地址或密钥。在伙伴设置点击「管理 Agent 模型配置」进入唯一的模型设置页；主窗对话、宠物对话、简报、文件摘要和屏幕问答全部复用这里的配置。仅在希望使用本机模型时，才选择 Ollama 原生协议并填写本机地址与已安装模型名；程序不会自动安装模型、启用备用服务或改写当前地址。
5. 主 Agent 或宠物「聊聊」中点击「文件摘要 / 选区问答」，先查看内容及目标模型地址，再点「确认发送资料并提问」。选区按 Esc 取消；截图需系统屏幕录制权限和支持视觉输入的模型。

## 统一 Agent 连接约定

- 唯一持久化配置为 `AppSettings.ai`，其中 `endpoint` 就是 `base_url`；主、副模型凭据都沿用 `SettingsService` 的安全存储，不写入伙伴偏好或主题包。不导入上游独立的 `AiProviderConfig`。
- `AgentDesktopService` 统一处理主窗/宠物聊天、确认后的文件与截图、晨间简报及连接测试。主副选择共用 `agent-model-config`，扩展新的 LLM 入口也必须经由现有 Agent 服务，不单独创建网络客户端或默认地址。
- 每次新请求读取最新设置；已经开始的请求沿用本轮连接，不中途重发。备用模型只有在现有路由允许且配置可用时接管可重试故障；已经输出部分流式文本则不切换，以免重复执行。
- 宠物的配置提示和对话历史开关订阅同一设置变更事件。资料尚在预览时修改配置，确认区同步显示当前主/备用模型及 API 路径；不显示 URL 中的用户名、密码或查询参数。预览本身不自动触发请求。
- 统一连接不代表给模型增加能力：选区问答仍要求所选模型支持视觉，文件内容仍只在用户确认后发送；图片主题的离线帧生成不调用 LLM 或生图 API。

## 动画与稳定性

- Live2D 每个角色保留自己的原模型实例，任务/专注/Agent/触摸只驱动动作；角色切换保留旧画面，直到新角色资源解码并绘出首帧。快速 A → B → A 切换不留下空画布。
- 同一浏览器窗口内使用一个共享 WebGL 绘图引擎，把每个模型的完整帧提交到其独立 2D 可见画布；不复用可变的 Cubism 模型实例。小窝、专注、小游戏和桌面头像可同时出现，尺寸、关节、视线及生命周期互不覆盖。
- 每次提交前检查真实像素 alpha，不把空白帧覆盖到宠物上。GPU 上下文丢失时保留上一帧，以有上限的退避重建绘图引擎；首次加载失败显示随包原模型截图，点击宠物可重试。保底截图仅用于异常/加载期间，不冒充动画。
- 首次出场以真实绘制完成为准，不依靠“两次 RAF 已过”判断；切换期间保留不透明的旧角色作为底层，新角色渐入后再释放旧实例，避免两层同时淡出造成半透明。
- 全部 48 种既有动作都有语义映射及连续关节曲线。兼容 `PARAM_ANGLE_X` 和 `ParamAngleX` 等参数名称，只驱动确实存在的头部、身体、耳朵、手臂、嘴部和眼睑，不创建无效虚拟参数，也不触碰透明度、部件开关和服装参数。
- 重复互动使用事件标识重启动作而不重挂模型；专注/思考/搜索/同步等长状态持续循环，跳绳与既有 820ms 起落节拍一致；姿态以缓动衔接，保留系统/用户的减少动态效果设置。
- 使用实际可见网格计算初始居中/脚底位置，排除透明命中区域；缓存边界，避免呼吸或触摸动作触发反复缩放。
- 原版动作遵循其已有肢体和道具；不新增伪装为原版的换色、服装或身体部件。补充跳绳/任务卡只为 TodoAgent 互动提供独立舞台道具和连续运动。
- 图片主题使用一张可见 Canvas 和两个离屏缓存；不用两张透明 DOM 画布轮流切换可见性。相邻帧按连续相位采样，不宣称它等同于 Live2D。
- 拖动松手速度只采样最近有效移动，重力和弹簧按真实时间积分，重新拖动或打开面板立即交还控制；不会在用户编辑面板时继续抛掷。

## 隐私、安全与当前边界

- 原版模型、主题、生成图片和偏好在本地；主题选择独立存储，不迁移或清空账号、真实任务和密钥。移除自定义主题时移到本机 `pet/removed-themes` 归档，可人工恢复。
- 文件入口只接受 UTF-8 文本/代码，最大 1MB、发送正文最多 24,000 字符；不支持 PDF/Word 二进制解析，截断会显式提示。
- 截图在用户确定矩形后才采集所选显示器，裁剪到选区，最长边限制为 1,600px。发送前展示预览和当前主/备用模型可能的去向；不会定时采集屏幕。
- 预览引用绑定当前窗口、10 分钟过期、一次消费；原始附件不进入会话历史或审计记录。模型回答本身可能引用资料内容，仍属于普通聊天历史。
- 含外部文件/截图的本次问答不开放任何工具，防止资料中的提示注入变成任务写入或本机命令；后续执行请再发送明确指令。全权限模式也不会绕过这条资料隔离。
- 本轮自动化验收未使用用户真实模型、飞书账号、系统屏幕授权或上传任何真实资料。原生 Ollama、取消选区和截图确认使用本机隔离测试服务/屏幕数据验证；真实模型效果、权限和 Windows 设备仍是外部验收项。
- [DesktopBuddy](https://github.com/DCDingCong/desktopbuddy) 的 MIT 代码许可不覆盖 Live2D 模型和 Cubism Core。保留 [Live2D 样例条款](https://www.live2d.com/eula/live2d-sample-model-terms_en.html) 与 [SDK 条款](https://www.live2d.com/eula/live2d-proprietary-software-license-agreement_en.html) 的独立要求；本轮不自动发布远程 Release。
