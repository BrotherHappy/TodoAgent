最后更新：2026-08-29（Todo Pet 原生桌面形态；本轮补充真实用户路径走查、clawd-on-desk 能力融合和桌面回归，真实模型和飞书事实沿用此前授权验收）

本记录只列出可复现事实、已完成修复和仍待验证的外部条件；不包含用户任务内容、凭据或密钥。

## 2026-08-29 真实用户走查（当前迭代）

本轮按一名个人用户的连续路径复核：启动应用 → 查看今天/全部任务 → 打开详情 → 编辑与完成 → 开始/暂停专注 → 补记投入 → 查看宠物浮窗 → Agent 对话 → 飞书同步 → 返回与重启。桌面端尝试使用隔离后台窗口，未抢占用户桌面，也没有在走查中弹出可见测试窗口。

### 走查中发现并修复

| 优先级 | 用户场景 | 复现问题 | 修复结果 |
|---|---|---|---|
| P1 | 打开一条历史上已经有专注记录、但来自旧版本的任务，在详情查看“记录投入” | 任务时间线和最近记录有数据，但“已累计”显示 0 分钟，用户会误以为历史投入丢失 | 新增共享的 `actualMinutesForTask` 统计规则：优先使用聚合值，兼容 `focusSessions` 和更早的 `focusElapsedSeconds`；详情、手动补记和主进程统一使用同一规则 |
| P1 | 飞书任务开始/暂停专注、恢复回收站任务、移动到今天、子任务完成 | 操作失败时原来可能只有未处理的 Promise，没有错误提示；移动到今天还可能先显示成功再静默失败 | 所有这些入口统一增加忙碌态、重复点击保护和中文错误回执；成功提示只在操作真正完成后出现，并保留可用的撤销入口 |
| P2 | 晨间简报点击“开始首项”、详情中的创建副本/打开飞书/删除操作 | 网络或权限异常时缺少明确反馈 | 改为统一捕获异常并提示下一步，不再把未完成的操作显示成成功 |
| P2 | 在宠物气泡、拖入任务卡或迷你任务列表中完成/安排任务 | 宠物动作失败时原来可能没有回执，用户无法判断任务是否真的改变 | 宠物侧任务完成、移到今天和互动记录统一捕获失败；失败会由宠物气泡给出可行动提示，成功动作才会触发庆祝反馈 |
| P2 | “今日盖章”组件的日期相关回归 | 固定旧日期的测试在跨日期运行时错误地期待“今日盖章” | 测试改为使用当前本地日历日，避免日期漂移造成假失败；产品行为不变 |

### 仍需真实设备补验

1. 在用户允许 Computer Use 后，用实际鼠标复验 macOS 的宠物拖动、悬停 1 秒展开、离开整体收起与多显示器边界。
2. 在 Windows 实机复验窗口置顶、系统托盘二次启动恢复和高 DPI 下的宠物气泡布局。
3. 使用真实飞书账号做一次“客户端反向修改 → 应用回拉”和断网恢复，确认外部网络状态而不是本地 Mock 行为。

### 本轮新增：clawd-on-desk 能力融合

- 对照目标项目的公开实现复核了多 Agent 状态、权限气泡、状态驱动动作、位置记忆、置顶和启动恢复等体验；Todo Agent 采用原创实现，不复制目标项目的 AGPL 代码或素材。
- 新增本机 `127.0.0.1` 外部 Agent 活动桥接：Token 认证、动态端口、运行时描述文件最小化、允许列表、16 KiB 请求上限、会话去重/过期和内存隔离均有单元测试覆盖。
- `SessionStart`、`UserPromptSubmit`、`PreToolUse`、`SubagentStart`、`PermissionRequest`、`PreCompact`、`WorktreeCreate`、`PostToolUseFailure`、`Stop`、`SessionEnd` 等事件会投影为宠物的思考、执行、并行抛球、等待确认、整理、搬运、错误和注意动作；外部权限不会被 Todo Agent 自动批准。
- 活动桥接默认关闭，设置页可配置 Agent 白名单、过期时间、显示开关和 Token 轮换；活动不写入任务、聊天历史、审计导出或飞书同步。
- 新增右键“边缘收纳”：窗口管理器把仅宠物形态停到当前显示器左/右边缘，保留可点击探头；鼠标移入由渲染层恢复，移出整个宠物区域后自动重新收纳，拖动和展开会先还原用户位置。
- 边缘收纳下的错误、等待确认和注意状态会短暂自动探头，普通工作状态不会打扰桌面；位置锁定不再阻塞用户明确开启的边缘收纳。

## 本轮修复

| 等级 | 问题 | 修复与回归 |
|---|---|---|
| P1 | 详情连续编辑可能被晚到旧保存结果覆盖 | 渲染端按用户输入顺序串行更新；详情字段使用修订号，旧请求不会清空新草稿。连续日期改回原值的真实 UI 与控制器回归均通过。 |
| P1 | 搜索词在切换“全部任务”“已完成”或来源后仍悄然生效，导致非零侧栏计数与空列表矛盾 | 显式打开任务集合（含重复点击当前集合）会清空临时查询，并重置当前集合的二级筛选；搜索框新增清除按钮，空结果准确说明是“没有匹配项”而非“没有已完成任务”。真实打包应用与新增 E2E 均通过。 |
| P1 | Agent 对不匹配/未绑定飞书来源的写操作可能越界 | Agent 对飞书来源与账号严格失败关闭；批量操作、撤销与状态变化均返回可信同步回执。 |
| P1 | Agent 工具失败后可能留下空白对话终态 | 失败统一显示可行动状态，绝不把未知结果写成成功；真实模型曾出现一次短暂网络错误，界面正确显示失败，重试后成功同步。 |
| P1 | 飞书创建后若后续字段失败，可能丢失远端标识并重建重复任务 | 创建成功立即持久化远端 GUID；待同步记录按账号精确匹配，离线恢复不会误联网，精确 404 才会触发恢复路径。 |
| P1 | 飞书全量列表缺席会误判为远端删除 | `my_tasks` 不完整时不再软删除本地映射；仅显式删除事件或精确 GUID 查询 404 才允许标记删除。 |
| P1 | 飞书任务的完成/重开、Agent 日期修改未必立即写回 | 本地直接操作与 Agent 工具均产生同步队列和可信回执；真实 UI 验证标题、备注、完成/重开，以及开始/截止时间自动同步。 |
| P1 | 浮窗“打开主窗口”在刷新时可能丢失目标页面 | 预加载层缓存导航事件；异步读取悬停设置后会重新排定计时，防止默认延迟失效。 |

| P2 | 窄浮窗内长 Markdown 表格会逐字竖排 | 表格置于专属横向滚动容器；主界面与浮窗的 Markdown 均可读。 |
| P2 | 任务页成功提示会遮挡切换后的工作台 | 切换任务页时清理无操作成功提示，错误和可操作提示保留。 |

## 可见 UI 验收事实

- 本地：通过主界面创建并编辑一条本地验收任务，验证备注、项目、标签、高优先级和私人计划；切换页面、搜索、Today/全部任务、完成、重开、再次完成、移入回收站与恢复均成功。连续将计划日改为明天后改回今天，最终值正确。
- Agent：真实模型的回复可流式显示；在主界面以自然语言创建、查询、改备注和优先级、完成、重开一条本地验收任务。回复中的 Markdown 表格以表格结构呈现，切换 Today 与 Agent 后会话仍保留。
- 飞书：主界面创建明确飞书来源的验收任务后自动同步；标题、备注、完成和重开均在未点击“立即同步”的情况下回到 `已同步`。随后 Agent 将该任务的开始时间设为次日 09:00、截止时间设为次日 18:00，收到可信同步回执；重启应用后这两个时间和同步状态仍正确。
- Todo Pet：关闭主窗口后仍置顶可见；任务上下轮播在鼠标停留时暂停；可在小窗切换全部、今天、专注、聊聊和小窝，长 Markdown 可滚动；专注暂停/继续/结束和完整小窝导航已走通。
- 搜索：在当前打包应用输入一个无匹配关键词后，显式进入“已完成”会自动恢复完成列表；点击清除搜索按钮和进入“全部任务”也会恢复对应集合。
- 验收结束时，所有本地 `Codex验收-...` 数据均已移入可恢复回收站。剩余可见的验收数据全部是飞书来源，因未获永久删除授权而保留。

## 飞书数据范围说明

飞书 Task V2 的“列取任务列表”接口当前只支持 `my_tasks`，即“我负责的”任务；仅作为关注人、或未归属给当前账号负责的任务，不会通过这个接口被导入。官方说明见：[列取任务列表](https://open.feishu.cn/document/task-v2/task/list?lang=zh-CN)。

产品已保证列表暂时缺席不会误删本地已映射任务。若需要同步每个可访问清单中的全部任务，应另行扩展为枚举可读取的任务清单并分别拉取清单任务；这需要对应权限与独立的产品设置。
