> 对应版本：`0.0.1`<br>

## 1. 状态口径

| 标记       | 含义                                                               |
| ---------- | ------------------------------------------------------------------ |
| 已实现     | 已有可运行代码和相应自动化测试，可进入人工验收                     |
| 待外部验证 | 协议与产品流程已实现，但必须使用真实账号、凭据、设备或签名环境验收 |
| 部分实现   | 核心链路可用，但尚未达到 PRD 对该模块的全部 P0 要求                |
| 后续版本   | 当前仓库未实现，属于 P1/P2 或移动端工作                            |

“已有代码”不等于“已经达到公开发布标准”。当前形态更适合定义为 **桌面端可验收 Alpha**；完成真实飞书、Windows 实机、签名分发、更多模型兼容矩阵及完整质量门禁后，才可升级为公开 Beta。

## 3. 已实现的关键安全边界

- 渲染层只可调用类型化白名单接口；不暴露 Node、通用 IPC 或 Electron 对象。
- 飞书 Token、每位用户专属 App Secret 和模型 API Key 使用系统安全存储；普通设置只保留凭据引用，日志、状态、IPC 和导出不含明文凭据。
- 本地任务不会因连接飞书而自动上传；私人计划、排序、专注等字段不进入飞书写入载荷。
- 模型只能提出严格 Schema 的工具调用，不能直接写本地数据；调用在执行前重新核对参数、目标、风险、基础版本和授权状态。
- 关闭任务标题与时间数据范围后，任务只以不透明本地 ID 和 `redacted` 标记进入模型；附件元数据与文本当前一律不进入模型。
- 网页、HTTP 和网络命令输出会被标记为不可信；同一轮研究后不能直接执行写入、命令或外部动作，必须等待用户下一条消息明确确认。
- 批量、外部和高风险动作需要确认或命中有效的精确临时授权；R4 禁区在全权限模式下也拒绝。
- 文件工具固定在 Agent 工作区内，并校验规范路径、符号链接和硬链接；网页读取阻止凭据 URL、私网目标和未复核重定向。
- 全局停止会阻止新的 Agent 工具调用并撤销临时全权限，但不停止本地提醒和飞书一致性队列。

这些边界已有单元/集成测试覆盖，但发布前仍应在实际打包应用、macOS 权限弹窗和 Windows 安全环境中重复验证。

## 4. 当前明确不应宣称完成的能力

以下能力在 PRD 中有目标或预留，但当前版本不应出现在发布宣传的“已支持”清单中：

- 独立可交互 Agent 浏览器、用户登录态浏览器和完整网页自动化。
- 容器或虚拟机级终端沙箱，以及任意宿主机权限的 OpenClaw 等价能力。
- MCP、Skills/插件、多 Agent、远程设备、桌面应用控制、邮件/日历/消息连接器。
- 可长期后台运行的自定义无人值守 Agent 工作流。
- 自动形成的长期记忆、语义检索、本地模型与多模型路由。
- 产品账号、跨设备云同步、完整移动端和移动推送。
- 经过签名、公证、自动更新和双平台全矩阵验证的公开发行版。

## 5. 验收证据与门禁

### 5.2 桌面本地验收

- [ ] 首次启动不登录、不连接飞书、不启用 AI，也能创建、编辑、完成、删除、恢复、搜索和重启恢复任务。
- [ ] 快捷键可从其他应用呼出快速录入；冲突时给出明确提示。
- [ ] 主窗口、悬浮窗、托盘/菜单栏、通知动作和 Today 始终指向同一任务实体。
- [ ] 到期、稍后、完成、安静时段、当天首次晨报、睡眠唤醒和通知去重均通过人工时间测试。
- [ ] 导出不含凭据；三种导入策略和选择性清除均在副本数据上完成恢复演练。
- [ ] 应用异常退出后任务文件、草稿、撤销记录、提醒状态和待同步队列无静默丢失。

### 5.3 飞书真实环境门禁

默认路径准备一个允许创建自建应用的真实飞书账号；同步能力验收再准备至少两个账号和不同任务角色。当前尚未执行以下真实浏览器授权：

- [ ] 第一条验证链接实际创建当前用户专属应用；显式用户权限为 Task v2 读写与离线授权，并记录飞书最小基座实际附带能力；租户管理员策略和拒绝路径文案正确。
- [ ] 客户端安全保存专属 App Secret 后自动打开第二条 Device OAuth URL；授权、刷新、撤权、重新授权和断开连接均成功。
- [ ] 重启后复用已有专属应用，重新授权不重复创建；普通设置、状态、日志、IPC 和导出不含 Secret 或 Token。
- [ ] 标题、描述、开始、截止、完成/重开、创建和删除的双向写入，与飞书界面逐项一致。
- [ ] 离线编辑跨重启保留；恢复网络后幂等收敛，不重复创建。
- [ ] 同一字段并发修改进入冲突，不静默覆盖；三种处理结果都正确。
- [ ] 无权限、Token 失效、限流、远端删除、分页和增量游标行为可恢复。
- [ ] 单负责人、会签、或签、关注人和只读成员形成带接口版本的能力矩阵；会签个人完成因 OpenAPI 不支持而正确禁用并跳转飞书。
- [ ] 若准备公开支持高级 Relay 模式，再用可信 HTTPS Relay 单独验证授权、刷新、撤权和服务端密钥隔离；Relay 不阻塞默认零服务器路径验收。

在这组门禁完成前，只能表述为“飞书零服务器连接与同步流程已实现并通过 Mock 自动化，等待真实账号/租户验收”，不能表述为“真实飞书登录已打通”或“飞书全部能力已验证”。详细范围见 [FEISHU_CONNECTION.md](./FEISHU_CONNECTION.md)。

### 5.4 真实模型门禁

已使用隔离临时配置连接 `http://10.30.0.21:8005/v1` 的 `DeepSeek-V4-Flash-0731`。真实端到端测试已通过：连接与精确 Token 回报、自然语言只读查询、自然语言创建本地任务、原生多轮 `tool_calls`、R2 批量更新预览与单次批准、结果落库，以及只读 AI 晨间简报。测试任务随临时配置清除，未写入用户真实任务库。由于模型会偶尔省略值为空的工具字段，工具说明已明确要求所有必填字段及显式 `null`，本地严格 Schema 和权限判断保持不变。

为每个准备支持的 OpenAI-compatible 提供方分别验证：

- [ ] Key 保存、替换和删除；请求只发送到用户确认的 Endpoint Origin。
- [ ] 普通对话、任务查询、单条修改、批量预览、拒绝、仅本次批准、临时全权限和停止运行。
- [ ] 原生 `tool_calls` 多轮回传、非法参数、未知工具、重复调用 ID、超时、429、5xx、断网和额度不足。
- [ ] 关闭备注、飞书内容、附件文本或聊天历史后，后续请求立即裁剪相应字段。
- [ ] 明文 Key 不出现在提示、错误、日志、审计、导出或截图中。
- [ ] 网页提示注入不能扩权、修改审计、读取密钥或把不可信内容直接转成写入/命令参数。

## 6. 建议的后续顺序

1. **封板桌面本地核心**：补齐仍暴露在 UI 中的 P0 任务字段和提醒动作，完成数据恢复、性能与无障碍验收。
2. **完成外部门禁**：真实 DeepSeek 基线已跑通；下一步用真实飞书账号完成专属应用创建、Device OAuth 和 Task v2 读写，Relay 仅在决定公开支持高级兼容模式时单独验收；同时扩展更多模型提供方的错误与长会话矩阵。
3. **收紧广权限 Agent**：决定 P0 是明确降级为“限定工具集”，还是补建独立浏览器与真正的终端沙箱；发布文案必须与实现一致。
4. **完成桌面分发**：签名、公证、Windows 实机和安装升级矩阵通过后进入公开 Beta。
5. **再启动移动端**：先建设账号、端到端同步、推送和冲突协议，再做 iOS/Android 的 Today、捕获、通知、Agent 对话和待批准操作；不要直接移植桌面悬浮窗交互。
