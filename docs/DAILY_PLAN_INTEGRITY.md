# 今日规划与同步数据完整性

更新：2026-08-31。适用于 `0.0.1` 及后续版本。

## 已修复的问题

“一起排今天”确认时曾出现 `tasks:apply-today-plan` / `Task title cannot be empty`。并非用户没给计划命名：一条历史飞书任务的本地标题为空，而同一账号、同一任务的同步缓存仍保留原有标题。旧同步逻辑把接口中缺失的 `summary` 转为空字符串，先写入任务文件，再因空标题无法保存同步基线；随后私人计划更新又校验整个任务，导致一条异常记录挡住整批计划。

修复不清空任务、不要求重新登录，也不通过跳过异常任务偷偷缩小确认范围。已有缓存足以证明原有标题时，初始化同步会只恢复该字段；没有可靠标题时保留原数据，规划界面显示“待补全标题的飞书任务”，仍可调整私人计划。此显示名称不会写入任务或上传飞书。

## 必须维持的约束

| 边界 | 行为 | 防止的问题 |
| --- | --- | --- |
| 创建 / 改标题 | 拒绝空白、不可见字符组成的标题和错误类型 | 新增无效任务 |
| 私人规划 | 只校验真正修改的 `plannedDate`、`privateOrder`、`estimatedMinutes` | 无关历史字段阻断规划、标题被顺手裁剪、错误触发飞书写回 |
| 批量确认 | 共享请求合同；先校验输入、任务状态、预览基线，再在一个本地事务中写入 | 重复 ID、失效预览、部分任务成功而其余失败 |
| 撤销 | 保留整批计划的一次撤销；后续修改冲突时拒绝覆盖新值 | 撤销覆盖新编辑 |
| 飞书拉取 | 缺标题先按同一 GUID 补读详情；仍无效时隔离该项、保留本地内容并继续正常项 | 把接口字段缺失当成删除指令 |
| 重试游标 | 有无效记录时不越过该批数据；下一次重新全量核对 | 永远漏掉稍后恢复的任务 |
| 飞书写回 | 创建和改标题的请求先校验；部分响应补读详情后才确认成功 | 成功写回后误清本地标题、错误重复写回 |
| 创建中断 | 收到真实 GUID 后先保存待确认映射，再读取详情 / 执行后续步骤 | 网络中断或重启后重复创建飞书任务 |

部分创建响应的待确认检查点使用本次已提交的合法内容，不把它当成最终远端事实。详情不可用时仍保留待同步 / 离线状态和真实 GUID，后续按同一 GUID 核对，不能宣称已经同步成功。

恢复历史标题只允许来自同一账号 / 授权身份 / GUID 的已知缓存；不得推测、借用别人的任务标题，或覆盖用户刚刚填写的新标题。私人笔记、日期、排序、完成状态及同步状态不随标题修复而改变。

## 出错时的交互

- 不再向用户直接展示 Electron 方法名、异常类、校验载荷或长调用栈。
- 今日规划保留已经选中的任务和手动时长，给出中文原因及“刷新并重新预览”。刷新只重新读取，不自动执行计划。
- 重复点击确认不会并发提交。同一批任务全部成功或全部不写入，不以“部分成功”掩盖错误。
- 磁盘空间 / 写入权限错误给出对应下一步；未确认的保存结果不会显示成功。
- 整个规划编辑区可滚动；错误条和底部操作栏位于滚动区外。窄窗口、长任务名和错误换行不能遮住重试或确认按钮。

## 回归用例与门禁

所有自动测试使用隔离数据目录和伪飞书接口。不得拿用户真实任务做增删改查验收，也不得为测试弹出主窗口或系统授权框。

| 测试 | 覆盖 |
| --- | --- |
| `tests/task-planning-integrity.test.ts` | 8 项含历史空标题的计划、一次撤销、私人字段隔离、输入校验、失败无文件 / 历史写入 |
| `tests/feishu-title-persistence.test.ts` | 两个真实持久化文件、空标题拉取隔离、重启后离线恢复、无远端写入 |
| `tests/feishu-sync-service.test.ts` | 缺字段详情补读、坏记录不阻断正常记录、同一身份恢复、增量重试、部分创建 / 修改 / 完成 / 重开响应、断网后不重复创建 |
| `tests/feishu-sync.test.ts` | 输入 / 输出标题边界、无关字段更新不改标题 |

修改任务校验、批量操作、同步映射、计划面板时，至少执行：

```bash
npm run typecheck
npm test
npm run build
npx playwright test tests/e2e/daily-plan-integrity.spec.ts tests/e2e/daily-plan.spec.ts --repeat-each=3 --workers=1
```

这两条桌面测试强制使用 `TODO_AGENT_E2E=1` 和 `TODO_AGENT_E2E_BACKGROUND=1`，隔离资料、关闭自动外部连接并在后台运行。安装包还应以 `TODO_AGENT_INSTALLED_EXECUTABLE` 指向打包后的可执行文件运行完整性测试，避免只验证开发版本。

本次先复现了 8 项计划被空标题阻断的失败，再修复至通过，并核查了实际截图。完整测试结果以当次运行输出和交付说明为准，不以永久写死的总数代替门禁。

## 仍然需要诚实说明的边界

这些保护避免的是本次空标题污染和整批规划失败，不保证外部接口、账号权限、网络和磁盘永不出错。没有已知标题且飞书详情仍不完整时，应保留数据并引导用户补全，不自动改名或删除。当前修复不代表对飞书所有可选字段做了完整 schema 迁移；后续新增字段也应区分“没有返回”与“明确清空”。
