# Todo Pet 动作图集与 Clawd 风格实现

更新时间：2026-08-30

## 目标

Todo Pet 采用原创透明动作图集作为默认桌面角色视觉层，解决 SVG 关节动画在小尺寸下“突然换姿势、道具和身体不在同一节奏”的问题。原有 SVG 保留在 DOM 中作为安全降级和交互覆盖层，不改变任务事实、权限和同步逻辑。图集现在按“入场帧 → 主循环 → 收势帧”播放，而不是把单张静态图当作动画。

视觉方向参考 `clawd-on-desk` 的状态驱动原则：角色始终置顶、透明背景、动作由 Agent 生命周期和桌面事件驱动、状态切换有明确语义，且 mini 模式仍然可读。参考实现的状态映射见 [clawd-on-desk state mapping](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/docs/guides/state-mapping.md)。

### 播放实现（当前版本）

> 当前运行时以 v23/v21 分页图集为准：主动作 577 格、互动动作 769 格，每段 63 个插帧。插帧器使用预乘透明度双线性采样；稳定身体沿连续轮廓过渡，绳子、星光、任务卡和地面阴影等独立道具按整层做透明度交接，关键帧保留原始像素，避免道具在最后一格突然出现；播放器保留分数播放头，但每次只提交一张完整帧，不把两张移动中的宠物叠成重影；下方早期版本数字仅保留作历史记录。

播放器使用 `requestAnimationFrame` 配合 Canvas 源矩形绘制，而不是用 `setInterval` 改 CSS 位移。每次从边界严格对齐的图集中精确裁出方形 cell，按设备实际刷新节奏采样；播放头保留小数相位，但每次只在隐藏缓冲中绘制一张就近的完整 cell，再切换可见缓冲，避免两张移动中的宠物重叠成重影。原始姿势之间在构建阶段用带符号距离场生成 63 个轮廓插帧，主动作由 10 帧扩展为 577 个播放帧，互动动作由 13 帧扩展为 769 个播放帧；睡眠、摸头和跳绳等连续动作也使用同一密度。运行时单格为 128px，再以设备像素比绘制到 Canvas，在不增加解码纹理宽度的前提下保持高密度动作。运行时先在隐藏 Canvas 完整绘制目标帧，再切换可见缓冲，避免 compositor 在清空和绘制之间采到半帧；图集尚未解码时保留上一张完整帧，冷启动才显示同动作 SVG 后备姿态。源矩形向内避开一像素邻格采样，缩放时不会把相邻姿势的耳朵、尾巴或道具带进来。插帧器不会把两个平移中的完整身体叠成重影：身体沿连续轮廓过渡，独立道具仍沿自己的位移层做预乘透明度交接；单侧出现/消失的手脚使用透明度交接，因此手、眼睛、耳朵和尾巴不会在中点硬切。Atlas Canvas 不再叠加旧的整宠物 CSS choreography；呼吸、摇摆和庆祝等位移只由同一图集时间轴负责，SVG 后备层仍保留交互特效，避免两个独立时间轴把角色拉向不同位置。运行时不把两套大幅位移叠在同一只宠物上；播放头会把异常的时间跳变限制为相邻逻辑姿势，绝不会跨越多格。循环动作采用“正向 → 反向”的往返序列，避免从最后一帧突然跳回第一帧；动作节拍会根据前几次 rAF 样本自适应 60/90/120/144Hz，并在刷新率估计切换时保持相位连续，避免高刷屏重复一帧或因节拍改变跨格跳跃。身体的呼吸只作用在 idle 的完整 canvas 上，且不会触碰图集偏移量。

为避免 macOS WebKit 对超宽纹理的隐式切片造成撕裂，v14/v12 运行时图集通过 `scripts/page-pet-atlas.mjs` 拆成每页 16 列、再按页纵向堆叠：逻辑帧顺序不变，但纹理宽度固定为 2048px（动作图集 2048×7168，互动图集 2048×9728），低于常见 GPU 纹理上限。`pet-atlas.ts` 只暴露分页后的网格，播放层无需在页边界做特殊分支，仍由双缓冲一次性呈现完整 cell。对于原始条带中混入的非同类姿态，动作映射只选取语义连续的源姿势区间（庆祝 6→7、漂浮 3→5、摸头 0→7、跳绳 3→8、睡眠 2→7），避免把“坐下/躺下”等无关关键帧串进同一循环。

播放器会在动作切换时从入场帧重新开始，并监听窗口尺寸和 `devicePixelRatio`，以高分辨率画布重绘。对于跳绳、搬运等身体锚点位移较大的片段，插帧器会平移单一完整姿态并在中点切换，避免 signed-distance 插值让两个身体轮廓同时成立；位移较小的片段仍使用轮廓插帧。播放时间采用受限的增量时钟：主线程偶尔被系统通知、窗口调整或 GC 卡住时，不会按墙钟一次跳过多格，而是最多推进一个显示节拍，宁可短暂放慢也不瞬移。这样每次呈现的姿态都与上一格相邻，不会因为忙碌帧出现跨格撕裂。系统开启“减少动态效果”时，循环会退化为一次静态/收势画面，不强行播放高频动效。

### 2026-08-30 动画连续性修复

本轮运行时素材已升级为 `todo-pet-motion-atlas-v18.png` 与 `todo-pet-interaction-atlas-v16.png`：主动作 433 格、互动动作 577 格，每两个原始姿势之间插入 47 个轮廓帧，单格 128px，分别按 16 列分页为 2048×14336 与 2048×18944。摸头只使用 0→6 的连续手部姿势段，避免后半段重复抬手造成“凭空消失”。插帧器现在让身体和独立道具分别沿自己的轮廓移动：身体使用较近的完整姿态，并对只存在于一侧的手脚做单侧透明交接；手、绳和星光等独立道具才使用预乘颜色混合，避免两只半透明身体叠在一起。Canvas 动作切换会保留上一张完整像素帧，用 5 个显示节拍完成短交接，再进入目标动作；交接只用于跨动作，不参与动作循环。

### 2026-08-30 播放时钟修复（v2.77）

上一轮图集已经足够密，但播放器把每次刷新硬限制为一格，导致 8ms 插帧在 60Hz 屏幕上被拉成慢动作；悬浮窗未聚焦时 Chromium 还可能进行后台降频。本轮将播放头改为按 `frameDurationMs` 累计逻辑时间：60Hz 会一次消化多个连续插帧、120Hz 通常一次一格，单次最多前进 4 格且在长卡顿时只保留两次刷新时长，不会跨越非相邻姿势。悬浮 BrowserWindow 明确关闭后台渲染降频，失焦时仍按显示节奏绘制。图集版本更新为 v18/v16，PNG 仍保持 2048px 宽度和双 Canvas 原子换帧。

### 2026-08-30 亚像素高帧插帧（v2.78）

上一版虽然把播放头速度恢复到真实时间，但在 128px 图集里仍会因为取样四舍五入出现“每移动半像素就跳一次”的撕裂感。本轮把插帧器的像素采样改为预乘透明度双线性采样，并把每段插帧从 47 增加到 63；播放器还保留分数播放头，把相邻过渡格合成为每个显示刷新对应的连续姿态。身体内部颜色沿同一条 SDF 轮廓连续混合，只在真正单侧出现的肢体上做透明度交接。这样既不产生双重身体，也不牺牲眼睛、手和尾巴的连续移动。新的 PNG 仍限制为 2048px 宽度，构建后由 PNG 尺寸、播放帧数、动作入口和安装版失焦采样共同验收。

- `src/assets/todo-pet-interaction-atlas-v12.png`：摸头、跳绳、搬运任务卡三组 289 帧播放序列，以及睡眠/起床等连续动作的分页运行时素材（16 列/页、19 页纵向堆叠，单格 128px）。v12/v10 宽条带保留为生成源快照。
- `src/assets/todo-pet-motion-atlas-v5.png` 与 `src/assets/todo-pet-interaction-atlas-v3.png`：GPT Image 原始高帧条带；通过 `scripts/pack-pet-atlas.mjs` 按测量的中心线和垂直窗口规整，再由 `scripts/interpolate-pet-atlas.mjs` 生成轮廓插帧后才进入运行时。
- `src/assets/todo-pet-action-atlas-v2.png`：保留为细分状态和异常状态的降级图集。

- 运行时主图集均为每格 128 × 128 的透明网格：逻辑动作帧为 577 / 769，页面固定为 16 × 16 格（每页 2048 × 2048，最后一页空格保持透明）。原始条带仍是 10 × 4 / 13 × 4 姿态源，打包脚本先按每帧中心裁切，再对下半身锚点与脚底基线做小范围校正，插帧脚本扩展到 63 个中间格，最后由分页脚本拆分为独立 GPU 页面，避免相邻帧串格、角色左右漂移或垂直跳动。
- 角色为 Todo Agent 原创的紫色小猫型伙伴，不复制 Clawd、Calico 或其他第三方角色。
- 图集只包含角色和与状态绑定的道具；不带 UI、文字、水印或网络资源。
- `src/renderer/pet-atlas.ts` 负责把所有 `PetAction` 映射到稳定的高帧序列、图集、网格尺寸和播放速度。
- `PetCharacter` 在动作状态切换时重置到入口帧，由统一的刷新同步循环播放；动作外层仍叠加呼吸、落位和互动覆盖层，不叠加第二个完整宠物轮廓。

## 动作编排规则

> 当前图集版本使用 577 / 769 格与 63 个插帧；以下旧版数字仅保留为历史记录，实施时以“2026-08-30 亚像素高帧插帧”小节和 `src/renderer/pet-atlas.ts` 为准。

1. 业务状态先于随机待机：等待确认、错误、完成、同步和专注不会被普通待机抢占。
2. 主动作使用 577 个播放帧，互动动作使用 769 个播放帧：每两个原始姿势之间插入 63 个轮廓插帧，前段负责进入，中段负责连续过渡与动作峰值，末段负责收势；快动作按约一个刷新周期播放，安静动作按两个周期播放，睡眠按四个周期播放，正向/反向播放避免首尾硬切。播放器根据 rAF 样本适配 60/90/120/144Hz，高刷屏不重复追赶；任何异常时间间隔都只能呈现相邻逻辑格，宁可短暂放慢也不跨帧瞬移。
3. 关键姿态由图集保证一致性，构建阶段的 signed-distance 插帧负责连续身体轮廓；绳子、星光、任务卡和地面阴影等独立道具按整层做预乘透明度交接，关键帧保持原始像素。运行时只对一张完整 cell 做 `globalCompositeOperation="copy"` 替换，按播放头就近选择相邻格，不把两张移动中的宠物叠成重影，也不在页面解码期间显示半透明空帧。idle 才保留极小的呼吸节奏，动作图集不再叠加第二套大幅 squash-and-stretch。
4. `thinking`、`working`、`juggling`、`notification`、`attention`、`sleeping` 等 Clawd 风格状态全部映射到可见姿态；多 Agent 使用 juggling，而不是只换一个徽章。
5. 跳绳、摸头、戳肚子、挠痒和击掌仍保留显式覆盖层，避免把用户手势和道具“画进身体”后无法正确打断。
6. 减少动态效果时，图集仍显示正确的关键姿态；动作状态仍可降速播放，原 SVG 仍作为 fallback。
7. 主题色会对图集做受限滤镜变体，任务、权限、飞书同步和 Agent 数据不会因为视觉层切换而改变。
