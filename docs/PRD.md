## 1. 产品概述

### 1.1 一句话定位

一个始终在桌面上的个人执行伙伴：统一本地与飞书任务，通过悬浮专注、快捷捕获和可选 AI Agent，帮助用户看清今天、管理任务，并在授权范围内操作网页、文件、终端和外部工具。

### 1.2 产品结构

产品由两个相互解耦的部分组成：

1. **可靠的桌面 TODO**：不注册、不连接飞书、不配置 AI，也可完整使用。
2. **可选的个人 Agent**：理解任务和工作节奏，通过对话管理任务、主动总结、查资料，并逐步扩展到浏览器、文件、终端、MCP、Skills 和子 Agent。

### 1.3 核心原则

- TODO 优先，Agent 增强。
- 本地优先，离线可用。
- 飞书保存团队事实，本产品保存私人计划。
- AI 可以关闭，模型故障不得阻断任务功能。
- Agent 行为可见、可确认、可审计、尽量可撤销。
- 主动但不打扰，用户决定提醒频率和主动程度。
- 普通模式安全可控，高级用户可开启全权限模式。
- Windows 与 macOS 保持相同数据语义，未来自然扩展到移动端。

## 2. 背景与问题

个人贡献者的任务通常分散在飞书任务、聊天消息、文档、网页、本地便签和脑中。主要问题包括：

1. 飞书任务和私人事项缺少统一入口。
2. 团队截止日期无法表达“我准备什么时候做”。
3. 打开完整任务应用成本较高，用户容易忘记查看。
4. 常规 TODO 只负责记录，不能主动总结和执行操作。
5. 通用 AI 能回答问题，但不了解任务事实，也不能可靠修改任务。
6. 通用 Agent 权限很大，却缺少适合普通用户的预览、撤销和权限解释。
7. 传统提醒容易造成通知疲劳。

## 3. 产品目标

| ID  | 目标                   | 验收方向                                       |
| --- | ---------------------- | ---------------------------------------------- |
| G1  | 降低记录成本           | 用户可在任意应用中于 5 秒内创建任务            |
| G2  | 统一任务入口           | 本地与飞书任务统一显示，并始终标明来源         |
| G3  | 建立每日执行闭环       | 支持晨报、Today、专注、完成/推迟和回顾         |

| G5  | 提供桌面常驻能力       | 用户不打开主窗口也能看到和处理当前任务         |

### 3.1 非目标

P0 不建设：

- 团队项目组合、审批、工时、甘特图和企业管理后台。
- 另一套团队聊天系统。
- Notion 式文档数据库平台。
- 自研基础大模型。
- 默认无人值守的完全自主 Agent。
- Skills 或插件开放市场。
- 完整 iOS/Android 客户端。
- 金融交易、密码导出、账号安全修改等高风险能力。
- 用私人计划日期覆盖飞书团队截止日期。

## 4. 目标用户

### 4.1 核心用户

飞书重度个人贡献者，包括产品经理、研发工程师、设计师、运营、市场人员、独立管理者及其他重度电脑工作者。

典型特征：

- 每天使用电脑工作六小时以上。
- 飞书中存在协作任务，同时需要记录私人事项。
- 经常忘记查看任务列表，或难以判断今天的优先事项。
- 希望快速记录和完成任务，不愿维护复杂项目系统。
- 愿意选择性接入自己的模型 API。
- 对自动化有需求，但希望明确控制权限。

### 4.2 次级用户

不使用飞书、只需要本地 TODO、悬浮专注和 AI 助手的普通个人用户。

### 4.3 核心用户任务

- 当我突然想到一件事时，我希望无需切换窗口就能记录。
- 当我开始一天工作时，我希望快速知道今天最重要的事情。
- 当我面对多个飞书任务时，我希望安排自己的执行顺序，而不改变团队截止日期。
- 当我不想手工整理任务时，我希望通过对话批量处理。
- 当任务需要研究时，我希望 Agent 查资料并转化为行动项。
- 当我授权时，我希望 Agent 能操作网页、文件和本机工具。
- 当 Agent 将产生较大影响时，我希望先看到范围和后果。
- 当出现错误时，我希望知道哪些操作成功、失败或尚未同步。

### 5.3 P2：OpenClaw 级高级模式

- 第三方 Skills 和插件。

## 7. 核心数据模型

### 7.1 任务字段

#### 标识与来源

- 本地任务 ID。
- 外部任务 ID。
- 来源类型与来源账号。
- 飞书租户。
- 远端版本。
- 创建时间、更新时间。

#### 内容

- 标题、富文本备注、状态、优先级。
- 项目/清单、分区、标签。
- 负责人、关注人。
- 附件和外部链接。

#### 时间

- 私人计划日期。
- 开始时间。
- 截止时间。
- 时间块。
- 提醒。
- 完成时间。
- 重复规则。

#### 结构与执行

- 父任务、子任务、依赖关系、自定义字段。
- 预计时长、实际时长、当前专注状态、专注记录、私人排序。

#### 同步

- 同步状态。
- 最近同步时间。
- 失败原因。
- 冲突字段。
- 删除墓碑。

### 7.2 日期语义

| 字段         | 含义                       | 是否同步飞书   |
| ------------ | -------------------------- | -------------- |
| 私人计划日期 | 用户计划哪天处理           | 否             |
| 开始时间     | 任务从何时可开始或正式开始 | 支持时同步     |
| 截止时间     | 团队或事实上的最终期限     | 是             |
| 时间块       | 用户计划在哪个时间段执行   | 否             |
| 提醒时间     | 何时通知用户               | 按来源能力映射 |
| 完成时间     | 实际完成时间               | 是             |

### 7.3 三层任务模型

1. **飞书共享事实层**：标题、描述、开始/截止、状态、负责人、任务清单等。
2. **本产品私人计划层**：Today、私人排序、时间块、专注记录、私人标签、私人备注和额外提醒。
3. **完全本地任务**：默认不上传飞书。

| FS-16 | 默认使用零服务器 `personal-direct`：为当前用户创建专属应用，再通过 Device OAuth 授权账号            | P0     |
| FS-17 | App Secret、Device Code 和 Token 不得暴露给渲染层；持久化 Secret/Token 必须使用系统安全存储         | P0     |

默认连接由两个明确阶段组成：先在系统浏览器确认创建当前用户专属应用，再自动打开第二条 Device OAuth URL 授权任务访问。第一阶段成功不等于“已连接”，只有第二阶段取得并安全保存用户 Token 后才进入连接状态。重新授权应在安全凭据仍存在时复用专属应用，不重复创建。租户禁止成员创建应用时，产品应说明需要管理员批准，并提供“使用已有飞书应用（零服务器）”入口：输入 App ID/Secret 后跳过注册，直接进入 Device OAuth；不得绕过租户策略。详细技术与验收边界见 [FEISHU_CONNECTION.md](./FEISHU_CONNECTION.md)。

P0 字段与操作矩阵：

| 字段或操作                               | 读取/导入          | 本产品内编辑               | 回写飞书                               | 不支持或无权限时           |
| ---------------------------------------- | ------------------ | -------------------------- | -------------------------------------- | -------------------------- |
| 标题、描述、开始时间、截止时间、完成状态 | 是                 | 是                         | 双向                                   | 字段转只读并显示原因       |
| 新建飞书任务                             | —                  | 用户明确选择飞书来源后创建 | 使用幂等键创建远端任务                 | 禁用飞书来源并可改存本地   |
| 完成与重开                               | 是                 | 本地即时反馈               | 带远端版本条件回写                     | 保留排队状态或转只读       |
| 删除飞书任务                             | 是                 | 与“转为本地副本”分开呈现   | 有删除权限时删除远端并保留墓碑至确认   | 禁用删除并提供“在飞书处理” |
| 转为本地副本                             | 是                 | 是                         | 不删除远端；创建独立本地副本并解除同步 | 明确提示会产生两个独立任务 |
| 任务清单、分区                           | 是                 | P0 只读                    | P0 不回写                              | 显示只读值及“在飞书中修改” |
| 子任务关系                               | 是                 | P0 只读                    | P0 不回写                              | 保留层级并提供飞书跳转     |
| 负责人、关注人                           | 是                 | P0 只读                    | P0 不回写                              | 不显示可编辑控件           |
| 重复规则                                 | 是并原样保留       | P0 只读                    | P0 不修改规则；实例完成按接口能力回写  | 显示规则及能力说明         |
| 飞书提醒                                 | 读取一个可映射提醒 | 可新增本地提醒             | P0 不修改远端提醒                      | 标记“仅本地提醒”           |
| 评论、附件、自定义字段                   | 元数据展示或跳转   | P0 不编辑                  | P0 不回写                              | 提供飞书跳转               |
| Today、私人排序、时间块、专注记录        | 本产品生成         | 是                         | 永不回写                               | 始终标记“私人”             |

“删除飞书任务”始终表示尝试删除远端实体；“从本产品隐藏”“转为本地副本”和“解除飞书账号”是不同操作，不得复用同一按钮或文案。任何字段能力在发布前必须通过真实租户、不同权限角色和接口版本的能力矩阵测试。

多负责人完成规则：飞书 `mode=1` 为会签、`mode=2` 为或签。当前 Task v2 OpenAPI 的完成接口只支持整体完成，不支持单独完成某位负责人的部分，因此会签任务在本产品中不得出现可用的“完成我的部分”按钮；应显示原因并提供“在飞书中完成”。或签/单负责人任务可显示“完成任务”，关注人、访客或只读成员不显示可写完成按钮。点击可用动作后先显示“正在提交”，只有飞书确认整体状态后才进入最终完成；失败时保留原状态并显示重试。AI 批量完成预览必须逐项区分“完成任务 / 需在飞书完成会签 / 无权完成”，不能用一个总数掩盖语义差异。

同步状态：本地、已同步、待同步、同步中、离线排队、同步失败、冲突、只读、权限不足、远端已删除。

同字段冲突时展示本地值、飞书值和最后修改时间，支持采用本地、采用飞书或逐字段处理。客户端应在写入前重新拉取并比较基线；如果目标接口提供条件版本参数则必须使用。当前飞书 Task v2 更新接口没有可依赖的条件版本参数，因此还需写后读取确认并保留并发窗口告警；只有飞书确认成功才标记“已同步”，失败时继续保留冲突与重试入口，不得宣称数据库级原子比较交换。

### 8.6 晨间简报

晨报包含：逾期、今日到期、今日计划、昨日未完成、未来三天高优先级事项、飞书变化、同步失败、预计工作量和 1–3 项重点建议。

生成流程：程序确定性统计事实 → 结构化快照 → 可选模型总结 → 模型不可用时显示模板摘要。

触发方式：每日设定时间、当天首次启动、睡眠唤醒补发、手动查看；遵守安静时段和休息日。

操作：帮我安排今天、开始首要任务、查看全部、稍后提醒、今天不再提醒。AI 提出的 Today 计划必须确认，并且只能修改私人计划层。

### 8.7 对话式任务 Agent

Agent 只能通过类型化工具操作任务，不得直接修改数据库。核心工具：

- `list_tasks`
- `get_task`
- `create_task`
- `update_task`
- `complete_task`
- `move_to_today`
- `set_reminder`
- `delete_task`
- `batch_update_tasks`
- `undo_task_operation`

规则：

- 明确的单条本地可逆操作可直接执行并提供撤销。
- 模糊指令必须要求补充。
- 主动建议不得自动执行。
- 批量、删除、循环系列和外部写入必须先生成确定性差异预览。标准模式必须展示并由用户确认；交互式全权限只有在命中有效精确预授权时才可免逐次确认，但仍须在执行详情中显示同一差异并提供停止、撤销或恢复入口。
- 预览展示数量、来源、字段、原值和新值。
- 部分成功必须逐项报告。
- 执行完成后生成审计记录。

### 8.8 研究与通用问答

Agent 支持简单问答、公开网页搜索和读取、多来源总结、显示来源和查询时间、将结果附加到任务，以及将结论转换为待确认的行动项。

研究与行动采用强制的两阶段隔离：

1. **研究阶段**仅允许搜索、网页读取和任务只读查询，输出结构化结论、来源和候选行动项。
2. **行动阶段**从结构化结论重新生成类型化操作计划，再经过当前权限规则、影响预览和必要确认后执行。

网页、邮件、附件和工具结果均视为不可信数据，不能成为授权依据，也不能直接拼接为终端命令、浏览器提交、文件路径或其他写入工具参数。模型必须从允许的枚举和用户已授权范围内重新构造参数；越界或低置信度时停止并请求用户选择。

### 8.9 Persona 与记忆

人格预设：极简秘书、温和伙伴、冷静教练、严格执行者。

可设置名称、头像、称呼、语气、回复长度、主动程度、提醒强度、工作时间、安静时段和是否指出计划过载。Persona 只影响表达，不影响权限。

P0 只保存本次会话上下文、Agent 身份，以及用户主动保存的工作时间、休息日、常用项目、计划习惯等基础偏好；默认不从对话、网页或飞书内容自动形成长期记忆。

P1 增加自动归纳的长期记忆、每日摘要和语义检索。无论版本，用户都可以查看来源和时间、编辑、删除、清空、设置有效期和仅本设备；禁止把网页内容或飞书任务正文自动升级为长期人格记忆。

### 8.10 Agent 权限

风险等级：

| 等级         | 示例                                         | 标准模式     | 交互式全权限                 |
| ------------ | -------------------------------------------- | ------------ | ---------------------------- |
| R0 只读      | 查询任务、读取公开网页、生成总结             | 自动         | 自动                         |
| R1 本地可逆  | 新建或修改单条本地任务                       | 自动并可撤销 | 自动并可撤销                 |
| R2 外部/批量 | 修改飞书、批量改期、写入限定文件             | 预览确认     | 在已验证的精确授权范围内自动 |
| R3 高风险    | 删除、网页提交、终端、设备控制               | 每次确认     | 在已验证的精确授权范围内自动 |
| R4 系统禁区  | 自行扩权、读取明文密钥、关闭审计、隐藏持久化 | 永久禁止     | 永久禁止                     |

权限可限定到账号、任务来源、项目/清单、域名、文件夹、命令、应用、设备、有效期、前后台、次数和预算。

P0 标准模式不提供永久授权：R2 可选择允许本次或对精确范围允许至当前会话结束；R3 只能允许本次。用户随时可以拒绝或撤销授权。交互式全权限是独立模式，必须经过本机身份验证，并按 8.10 的有效期和范围运行。P1 才增加持久规则。

授权模式：

1. **只读模式**：只能查询、总结和规划。
2. **标准模式**：R0 自动，R1 自动并可撤销，R2 预览，R3 每次确认。
3. **自主模式（P1）**：用户为明确规则授予持续权限；仅在声明的前后台、有效期、次数和预算内运行，不构成永久系统级授权。
4. **交互式全权限模式（P0）**：既授予工具可用权，也代表用户对界面列出的工具、目标范围和有效期进行了预先行动授权。R2/R3 只有在该精确范围内才可免逐次确认；新工具、新账号、新目录、新域名、扩大写入范围或超预算仍需重新授权。R4 永远禁止。
5. **无人值守全权限（P1）**：只对预先定义的工作流生效，必须锁定目标、工具、账号/目录/域名、时间窗、次数、预算和结果送达位置；不得接受运行中出现的任意新目标，也不得继承交互式全权限。

P0 交互式全权限只能从本机设置开启，要求系统身份验证，支持“1 小时”或“直到应用进程退出”。设备一旦锁屏，或发生用户退出、应用进程退出、系统重启、全局停止、关闭 AI、撤销任一核心权限时立即暂停；恢复前必须重新验证。关闭主窗口但应用仍驻留后台不等于进程退出，界面必须明确说明这一点。

全权限状态在主应用、托盘/菜单栏和悬浮入口持续可见，并提供“停止 Agent”。高风险覆盖指标按模式解释：标准模式要求确认覆盖率 100%；全权限模式要求每个 R2/R3 调用均命中有效、未撤销且范围精确的预授权记录，覆盖率 100%。

### 8.12 后台自动化

触发条件包括指定时间、循环周期、当天首次启动、设备解锁、网络恢复、条件满足、周期 Heartbeat 和一次性提醒。

每个自动化保存名称和目标、创建者、Agent 和模型、工具与权限快照、时间和时区、补执行规则、最大运行时长、重试、并发、预算、结果送达位置和失败规则。

系统调度器分为两类：

1. **核心确定性服务**：任务提醒、飞书同步、离线队列重试和模板化晨报。关闭 AI 或停止 Agent 后仍继续运行；只有用户关闭对应提醒、断开飞书或退出应用进程时才停止。
2. **Agent 自动化**：任何需要模型或 Agent 工具的计划。关闭 AI、停止 Agent 或撤销权限后立即暂停。

Agent 自动化的运行时有效权限必须等于“创建时权限快照 ∩ 当前权限策略”。后续撤权、关闭 AI、停止 Agent、断开飞书、缩小目录/域名范围或降低权限模式均立即生效，旧快照不得继续授权。自动化不能自行扩大权限，也不自动继承创建后新增的权限。

P0 只提供第一方基础模板；P1 才开放自定义无人值守工作流。同一计划同一时间只运行一次；高风险操作可进入待批准队列。待批准项默认 24 小时过期，目标数据变化或权限版本变化时立即失效，不能重复批准旧计划；恢复时必须重新计算差异。达到预算、次数或循环阈值后自动停止。

### 8.13 审计与紧急停止

每次工具调用记录时间、发起者、模型、工具、目标、脱敏参数、授权依据、修改差异、费用、结果、错误和可撤销性。

用户可撤销适用操作、暂停自动化、断开模型或飞书、撤销权限、一键停止 Agent，并按数据保留策略导出或申请删除审计记录。

权限存储、凭据存储和审计追加日志与 Agent 可访问的文件/终端空间隔离；任何模式下 Agent 均不能读取密钥明文、修改权限规则、篡改或关闭审计。审计删除由产品受信任进程执行，并保留最小删除凭证，不由 Agent 工具执行。

“停止 Agent”后立即阻止新工具调用，取消可取消的模型请求、浏览器动作和 Agent 后台工作，终止由 Agent 启动且仍受控的子进程，并暂停未来 Agent 自动化。核心任务提醒、飞书同步和离线队列继续运行。对已发出的外部请求或已产生的不可逆影响，状态显示“正在停止”“已产生外部影响”“无法撤销”或“需要人工恢复”，不得伪装为已取消；同步队列保留数据一致性所需的补偿操作和完整审计。

### 8.14 账户与数据

- 本地任务免注册可用。
- 连接飞书默认不要求 Todo Agent 产品账号；未来跨设备同步可以单独要求登录产品账号。
- 飞书连接按用户和租户隔离。
- 本地任务不得因连接飞书而自动上传。
- API Key 默认不跨设备同步。
- 支持任务、会话、记忆、权限和审计导出。
- 支持删除产品账号和关联数据。
- 敏感凭据存入系统安全存储或专用加密凭据服务。

## 9. 核心用户流程

### 9.1 首次使用

进入本地首页 → 可选一键连接飞书 → 浏览器确认创建专属应用 → 自动打开第二条 Device OAuth URL → 授权当前飞书账号 → 可选启用 AI → 测试模型 → 选择 Agent 身份 → 设置晨报、安静时段、悬浮和开机启动 → 查看权限说明 → 进入 Today。飞书两阶段均可跳过或取消，本地任务始终可用。

### 9.2 快速捕获

按快捷键 → 输入自然语言 → 解析为 Chip → 用户检查 → 创建并关闭 → 成功反馈和撤销。

### 9.3 晨间规划

生成事实摘要 → 可选 AI 总结 → 用户选择“帮我安排今天” → Agent 生成私人 Today 计划 → 用户确认 → Today 更新，飞书截止日期不变。

### 9.4 对话批量操作

输入指令 → 查询匹配任务 → 生成数量、来源和字段差异 → 权限引擎检查 → 标准模式展示并等待确认 / 交互式全权限命中精确预授权后直接执行 → 执行和同步 → 返回逐项结果 → 撤销和审计。

### 9.5 研究转行动

提出问题 → Agent 搜索并给出来源 → 生成拟创建任务 → 用户选择来源 → 确认后创建。

### 9.6 高风险工具调用

Agent 请求调用 → 权限引擎检查 → 展示目标、范围、影响和可逆性 → 用户授权或拒绝 → 执行 → 审计与撤销。

### 9.7 飞书冲突

检测同字段并发修改 → 标记冲突 → 展示双方值和时间 → 用户选择处理方式 → 同步最终结果。

详细流程图见 [UX_INFORMATION_ARCHITECTURE.md](./UX_INFORMATION_ARCHITECTURE.md)。

## 10. 状态与异常

Agent 状态：未启用、就绪、思考中、等待授权、执行中、后台运行、已暂停、已停止、全权限、错误。

| 异常                       | 处理                                       |
| -------------------------- | ------------------------------------------ |
| 无网络                     | 保留本地功能，操作进入队列                 |
| 专属应用创建被租户阻止     | 说明需要管理员批准，并提供已有应用高级入口 |
| 飞书注册或 Device 链接过期 | 清理本次授权状态并允许重新一键连接         |
| 用户取消任一授权阶段       | 返回未连接状态，不开始同步或上传本地任务   |
| 飞书 Token 失效            | 暂停队列并引导重新授权                     |
| 飞书权限不足               | 任务转只读并说明原因                       |
| AI Key 无效                | 显示测试失败，不影响任务                   |
| 模型额度不足               | 降级模板摘要和普通任务查询                 |
| 模型返回非法工具参数       | 不执行并要求重试或澄清                     |
| 批量操作部分失败           | 逐项展示结果                               |
| 浏览器页面变化             | 停止当前操作并重新读取页面                 |
| 命令超时                   | 终止或请求继续                             |
| 锁屏或全权限到期           | 暂停 Agent，阻止新调用并要求重新验证       |
| 权限在后台任务运行前被撤销 | 以当前策略为准停止，旧权限快照不得继续使用 |
| 停止时外部影响已发生       | 显示已产生影响、可否补偿及人工恢复入口     |
| 定时任务错过               | 按规则补执行或跳过                         |
| 应用崩溃                   | 恢复草稿、队列和未完成事务                 |
| 同步限流                   | 退避重试并允许手动刷新                     |
| 远端删除                   | 提供删除、转本地或重新创建                 |

## 11. 无障碍与跨平台

- 核心流程可完全使用键盘。
- 焦点顺序与视觉顺序一致。
- 状态不能只依靠颜色。
- 正文对比度不低于 4.5:1。
- 主要点击目标不小于 44×44 逻辑像素。
- 支持字体放大至 200%、屏幕阅读器、高对比度、深浅色和减少动画。
- Windows 与 macOS 保持相同数据模型和同步语义。
- Windows 使用托盘，macOS 使用菜单栏。
- 支持 Windows 高 DPI、macOS Retina、Spaces 和多显示器。
- 重复启动时聚焦已有实例，避免数据库竞争。
- 安装包签名；macOS 完成签名和 notarization。
- P0 支持 Windows 10 22H2、Windows 11（x64；ARM64 先通过兼容层验收），以及 macOS 13 及以上（Apple Silicon 与 Intel）。Windows 原生 ARM64 列入 P1。
- 发布矩阵覆盖安装、升级、卸载保留数据、开机启动、系统权限恢复和自动更新失败回滚。

## 12. 非功能要求

### 12.1 性能

- 快捷录入暖启动 P95 ≤300ms。
- 悬浮面板展开 P95 ≤200ms。
- 本地任务操作提供即时反馈。
- 参考设备上空闲平均 CPU 目标 <1%。
- 参考设备上内存目标 <300MB。

### 12.2 同步与提醒

- 本地修改后 1 秒内启动同步。
- 网络正常时飞书修改一致时间 P95 ≤10 秒。
- 事件可用时远端变化到达 P95 目标 ≤30 秒。
- 常规同步成功率 ≥99.9%。
- 后台提醒触发误差不超过 ±1 分钟。
- 静默数据丢失或静默覆盖为 0。

### 12.3 可靠性与安全

- 无崩溃会话占比 ≥99.5%。
- 离线队列和自动化跨重启保留。
- 权限判断由确定性权限引擎执行，不依赖模型自律。
- 凭据不暴露给模型。
- 文件、浏览器和终端按 8.11 的范围契约隔离；路径解析、符号链接、私网、下载和环境继承均有自动化边界测试。
- 研究阶段与行动阶段使用不同工具白名单和新的权限检查，外部内容不得直接进入执行参数。
- Agent 不能自行开启全权限。
- Agent 工具无法访问权限、凭据和审计存储；相关边界在全权限模式下同样成立。
- 第三方工具必须声明来源、版本和权限。

## 13. 指标

北极星指标：**周有效执行用户数（WEAU）**——七天内至少在三个自然日使用产品，且累计完成不少于五项任务的用户数。

| 指标                             | Beta 目标 |
| -------------------------------- | --------: |
| 首次使用 10 分钟内创建或导入任务 |      ≥80% |
| 首日完成创建—加入 Today—完成闭环 |      ≥60% |
| 飞书目标用户首日完成连接         |      ≥70% |
| 启用 AI 用户完成首次对话操作     |      ≥60% |
| 快捷创建任务中位耗时             |     ≤5 秒 |
| 胶囊完成或推迟任务的操作次数     |     ≤2 次 |
| D7 留存                          |      ≥35% |
| D30 留存                         |      ≥20% |
| 因提醒过多关闭全部通知           |      ≤15% |
| 晨报“有帮助”比例                 |      ≥70% |

AI 目标：基准测试中明确单条 CRUD 正确率 ≥95%；批量匹配范围正确率 ≥95%；标准模式高风险确认覆盖率 100%；全权限模式有效精确预授权命中率 100%；未授权修改为 0；研究回答来源覆盖率 100%；修改型工具审计覆盖率 100%。

关键埋点包括 `app_open`、`quick_add_opened`、`task_created`、`task_completed`、`task_added_to_today`、`focus_started`、`morning_brief_viewed`、`agent_action_proposed`、`agent_action_approved`、`agent_action_denied`、`agent_action_executed`、`agent_action_undone`、`sync_conflict`、`full_access_enabled` 和 `emergency_stop_used`。埋点不得包含任务正文、密钥或未脱敏对话。

## 14. P0 发布验收标准

1. 未登录、未连接飞书、未配置 AI 时，本地 TODO 完整可用。
2. 用户可在任意应用中通过快捷键创建任务。
3. 本地和飞书任务在统一视图中不重复、不丢失，并标明来源。
4. P0 公布的飞书字段可完成双向同步。
5. 离线修改跨应用重启后仍可继续同步。
6. 同字段冲突不会被静默覆盖。
7. 飞书任务可加入私人 Today 而不修改远端截止日期。
8. 晨间简报 AI 不可用时仍能生成。
9. 批量、删除和飞书外部写入在标准模式下全部正确预览或确认。
10. 操作预览准确展示任务数量、来源、原值和新值。
11. 所有可逆任务操作提供撤销。
12. 权限测试中不存在未授权工具调用。
13. 全权限模式不能由模型、聊天、插件或自动化开启。
14. 交互式全权限不会自动赋予无人值守权限。
15. P0 全权限仅支持 1 小时或直到应用进程退出；锁屏、重启、撤权与停止规则全部通过测试。
16. 文件、浏览器、终端、剪贴板和截图的每个调用均符合类型化契约、范围校验和永久硬边界。
17. 自动化运行权限等于创建快照与当前策略的交集；撤权立即阻止后续调用。
18. 密钥不出现在提示、普通日志、导出或崩溃报告中。
19. 提示注入测试不能让研究内容直接形成可执行参数，也不能诱发未授权修改、外部发送或系统执行。
20. 修改型工具调用全部生成可查询且 Agent 不可篡改的审计记录。
21. 自动化跨重启保持状态且不会重复执行。
22. 达到预算、循环或超时阈值后 Agent 自动停止。
23. 全局停止 Agent 后不再开始新的工具调用，所有进行中动作进入明确终态。
24. Windows 与 macOS 均通过快捷键、悬浮、多屏、提醒、离线、同步和安装/升级/卸载矩阵。
25. 不存在已知静默数据丢失或静默覆盖问题。
26. 飞书会签、或签、单负责人和只读成员的完成语义及“不支持时跳转飞书”降级通过真实租户验收。
27. P0 标准模式不存在 R3 会话或永久授权；交互式全权限的每项 R3 调用均命中有效精确预授权。
28. 模型数据范围的字段裁剪、一次性授权、即时撤权和全权限不扩权全部通过测试。
29. 默认飞书连接无需 Todo Agent 服务器；专属应用创建、Device OAuth、凭据隔离、取消/过期和重启复用通过真实账号验收。

## 15. 开发验收顺序

### Gate A：可靠任务核心

本地数据模型、核心视图、搜索、提醒、循环、离线、回收站、撤销、快捷录入、托盘和悬浮胶囊。

### Gate B：飞书同步

专属应用一键创建、Device OAuth、凭据隔离、授权状态、字段映射、双向同步、队列、重试、冲突、删除和私人计划层；Relay 作为兼容路径独立验收。

### Gate C：任务 Agent

模型接入、晨间简报、任务问答、单条和批量 CRUD、操作预览、审计、Persona 和通知预算。

### Gate D：广权限 Agent

权限引擎、文件、沙箱终端、独立浏览器、基础自动化、全权限模式、紧急停止和安全测试。

前一 Gate 未达到数据可靠性标准，不进入下一 Gate 的公开测试。

## 16. 主要风险

| 风险                      | 缓解措施                            |
| ------------------------- | ----------------------------------- |
| P0 范围过大               | 使用四个 Gate 分阶段验收            |
| 飞书字段无法完全映射      | 字段能力矩阵及“仅本地”标识          |
| AI 误解批量范围           | 确定性查询、差异预览和确认          |
| 提示注入                  | 外部内容隔离、工具权限和沙箱        |
| 全权限造成破坏            | 本机开启、明显状态、审计和紧急停止  |
| 通知疲劳                  | 通知预算、安静时段和自动降频        |
| 模型成本不可控            | 预算、次数、超时和循环熔断          |
| 第三方插件供应链          | P0 仅第一方工具，后续审核和权限清单 |
| 桌面常驻资源过高          | 性能预算和参考设备测试              |
| 产品变成通用 Agent 而失焦 | 任务执行始终作为默认主页和核心循环  |

## 17. 已确定的产品决策

- 核心用户为个人贡献者。
- 产品面向普通个人用户，不建设独立企业版。
- 本地任务免注册。
- 首版本地 Agent，仅在电脑在线时运行。
- 默认一个可自定义助手。
- AI 完全可选。
- 飞书保存团队事实，本产品保存私人计划。
- 默认采用悬浮胶囊，悬浮球作为紧凑模式。
- Agent 最终覆盖与任务执行相关的 OpenClaw 主要能力类别，并以带日期/版本的矩阵持续验收。
- 标准模式分级确认。
- P0 高级用户可以开启交互式全权限；P1 才开放受限范围的无人值守全权限。
- 全权限仍不能读取明文密钥、自行扩权或关闭审计。
- 全权限是对精确工具范围与有效期的预授权，不是永久、无边界的系统控制权。
- P0 飞书同步范围以本 PRD 的字段与操作矩阵为准，不用“全部飞书能力”作宣传。
- P0 默认采用零服务器 `personal-direct` 两阶段连接；已有审核/发布应用可用 `existing-direct` 跳过注册；Relay 仅为兼容/高级方案，不是默认发布依赖。
